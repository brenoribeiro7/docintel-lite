# DocIntel Lite Architecture

## Purpose and boundaries

DocIntel Lite is a modular monolith for document-grounded question answering. This document records
the agreed architecture across milestones while separating implemented behavior from plans. Planned
components are not claims about current functionality.

## Milestone map

| Area | Decision | State |
| --- | --- | --- |
| Application shape | One modular FastAPI service with synchronous SQLAlchemy | Implemented in M1 |
| Source format | Textual PDF only; no OCR | Implemented in M1 |
| Binary retention | Do not persist the uploaded PDF | Implemented in M1 |
| Text model | Preserve normalized text page by page, including empty pages | Implemented in M1 |
| Persistence | PostgreSQL 18.6 with pgvector 0.8.6 enabled | Implemented in M1 |
| Chunking | 600-token chunks with 100-token overlap | Planned for M2 |
| Embeddings | OpenAI `text-embedding-3-small`, 1536 dimensions | Planned for M2 |
| Retrieval | Exact cosine search with `top_k = 4` | Planned for M2 |
| Answer model | `gpt-5.6-terra` through the Responses API | Planned for M2 |
| Answer policy | Document-grounded answers with abstention when evidence is insufficient | Planned for M2 |
| Citations | Source IDs created and controlled by the application | Planned for M2 |
| Orchestration | No agents, tools, or function calling | Planned constraint for M2 |
| Evaluation | Dedicated retrieval and answer-quality evaluation | Planned for M3 |

## Implemented in M1

The HTTP layer owns request validation and explicit response schemas. The document layer owns exact
hashing, PDF parsing, deterministic normalization, and transactional ingestion. The database layer
owns SQLAlchemy mappings and synchronous session lifecycle. Alembic is the sole schema-change path.

An upload is bounded before parsing. Its filename is sanitized as untrusted display metadata and is
never converted to a local path. pypdf extracts only textual page content. Unicode NFC, newline
canonicalization, inappropriate control-character removal, trailing line-whitespace trimming, and
blank-line bounding are deterministic. Empty pages are persisted to retain the PDF's real page
sequence, while a document whose aggregate normalized text is empty is rejected.

SHA-256 is computed over the original bytes. The unique database constraint is authoritative under
concurrent requests; both a pre-check and the constraint-race path return the existing document ID.
The binary input is not persisted. A document and all of its pages share one transaction, and the
foreign key cascades deletion.

The `vector` extension is installed now so the deployment prerequisite is observable through
readiness and integration tests. No chunk table, vector column, similarity query, or approximate
nearest-neighbor index exists in M1.

## Planned for M2

Indexing will begin from persisted page text, without changing ingestion's source-of-truth page
numbers. Chunk boundaries will target 600 tokens with a 100-token overlap. Embeddings will use
OpenAI `text-embedding-3-small` at 1536 dimensions and be stored in PostgreSQL/pgvector. The first
retrieval implementation will use exact cosine distance and return four candidates; HNSW and IVFFlat
are intentionally deferred until measurements justify an approximate index.

Question answering will use `gpt-5.6-terra` through the Responses API. Answers must remain grounded
in retrieved document evidence, abstain when support is insufficient, and cite only opaque source
IDs generated by the application. No agent loop, tool execution, or function calling is part of the
design.

## Planned for M3

Evaluation will measure retrieval relevance, grounded answer behavior, abstention, and citation
integrity against a controlled dataset. Its results will guide tuning; no evaluation dataset or
evaluation pipeline is present in M1.

## Security posture

M1 deliberately narrows the input surface to bounded, non-encrypted textual PDFs. It performs no
network access during ingestion, does not execute embedded content, and does not retain the original
binary. Authentication, multi-user isolation, OCR, object storage, and cloud deployment remain
outside the current system boundary.
